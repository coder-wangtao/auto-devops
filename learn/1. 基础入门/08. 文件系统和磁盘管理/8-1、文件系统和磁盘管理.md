文件系统和磁盘管理

1、文件系统

​	1）节点和块
	文件系统的最小存储单位为块
       a:小文件比较多的应用服务存储上，块小比较好,
       b:存储大容量时，大块比较好
       c:每个文件系统的开始位置的那个块就称为超级块（spuerblock）
         dumpe2fs  /dev/sda1
	文件或目录在硬盘上的存储分为属性存储（inode）和内容存储（block）
       a:inode 记录文件的相关属性以及文件内容放置在哪个块中（指针功能）
       b:块放的就是文件内容，对于目录来说存放的就是该目录下文件或目录的关联性

​	2）文件的读取（文件系统的解析）
	首先由跟目录获取该文件上层目录的所在的inode,再由该目录所记录文件关联性获取对应文件的inode,
	然后找到这个对应文件的相关属性和数据存放的地方，同时判断文件权限，有权限情况下，读取对应块中的内容

	3）文件删除
        删除掉的是指针，大容量的数据删除也很快。要进行数据恢复，原则上若无新数据写入，
	原来的数据块未被清除，这个数据是可以恢复的！找到对应的地址，数据连接是可以重新建立的。

​	4）空间满的问题（examples说明）
	一个10M左右的分区
	mkfs.ext3  -N  20  /dev/sdb1  
	dumpe2fs   /dev/sdb1
	dd  if=/dev/zero  of=n    bs=1K  count=1
	df  -h
	df  -ih

	5）区别
     	a:ext2  ext3  ---inode   128字节  ext4  256字节
     	b:文件系统大小和文件大小
        ext2   16TB   2TB
        ext3   16TB   2TB
        ext4   1EB    16TB
        Xfs    18EB   9EB   （64位文件系统）
     	c:日志功能（ext2 无，ext3和ext4有，ext4也可灵活关闭,xfs日志指定位置）-o^has_journal
     	d:文件索引方式不同（ext4 :extents    ext3 ext2:blockmaps）,文件读写效率变高！
     	e:多块分配和延迟分配
     	f：fsck变快（大系统中会有很大效果，fsck会去扫描在用的inode)
     	g: 默认启用barrier(-o barrier=0 关闭) 类似DB的日志功能，日志落地才能commit1
     	h: xfs_repair  -L  /dev/sda1

2、磁盘管理

	1）分区要点
	a:MBR(master boot recorder)主引导区
  	  一块硬盘第0磁道上
	  MBR前446字节包含可启动系统的引导加载程序的第一个部分，后跟包含分区表的64字节。在分区表中有关于四个主分区的信息的空间；分区开始位置，结束位置以及指出存储在其中的信息类型的代码。

	b:3P+1E    4P
   	MBR 最多4个分区的记忆
   	主分区  扩展分区  逻辑分区

	2）新建分区和删除分区（实例讲解）
      fdisk  -l   和df  -h   //剩余空间的判断
      fdisk  /dev/sdc       //fdisk后面跟硬盘名字，进行分区管理

	3）格式化系统和挂载
      mkfs.ext2  mkfs.ext3  mkfs.ext4  tune2fs     //文件系统相关的命令
      df   -h                                                 //查看系统目前有哪些
      mount /dev/sdc1  /mnt                       //将/dev/sdc1挂载到mnt目录上
      mkfs.ext4  -L “firstp”   /dev/sdc1        //对/dev/sdc1进行系统格式化，-L指定分区lable,可省
      mount  -L firstp  /mnt                         //指定label进行挂载，和指定分区挂载效果一样
      umount /dev/sdc1  ;umount  /mnt      //对分区或目录进行卸载，卸载后无法再通过目录操作分区了

	4）磁盘的一些相关的操作命令 
      fdisk   -l                         //查看目前有哪些磁盘，有哪些分区
      du  -sh       目录名        //用来确认目录的实际大小
      mount  -a                      //从/etc/fstab文件中读取行，并按配置将分区挂载上去

	5）/etc/fstab随机挂载
       a:新建分区随机启动
       b:分区/uuid号    挂载目录       文件系统        挂载参数          0   0
        备注：UUID (-U)：通用唯一标识符，如60ab619d-0db0-4d74-9951-c7bd3f67ed85。UUID通常是在创建文件系统时生成的，并且永不改变。
              可以通过tune2fs -l  /dev/sdb2 或dumpe2fs  /dev/sdb2来查看对应的分区的UUID号
              如果是xfs文件系统，可以使用xfs_admin  -u   /dev/sdb1  ，来确认对应分区的uuid号。
              或使用lsblk  --fs   /dev/sdb1来看

       6）fsck的作用
        文件系统只读时的处理步骤
        a、卸载设备  umount /dev/sdc1   
        b、fsck  -c  -y /dev/sdc1 (ext文件系统)
        c、xfs_repair  -L  /dev/sda1 （xfs文件系统）
        提醒：如果是根文件系统，请在急救模式下处理，挂载的时候，进行磁盘校验很容易出现数据丢失的问题。

3、交换分区
	1）交换分区概念
	交换分区，用于扩展系统的物理内存.交换分区为swap分区，系统内存使用紧张时，会将内存中不常用的数据暂时交换到swap分区中！
	Partition ID: 0x82
	使用swapon 激活交换分区
	使用swapoff 取消激活
	2）编辑/etc/fstab文件，以便在引导时自动激活交换分区 
	# cat /etc/fstab
	/dev/vgsrv/swap2	swap	swap	defaults 	0 0
	激活交换分区：swapon /dev/vda1   
	启用交换分区：swapon -a   //写在fstab文件中的可以被激活
	确定激活：swapon -s    //确认目前已经被激活的swap设备
	3）swap分区的增加
   	a:直接加分区格式为swap格式
   	b:建立虚拟内存文件，格式为swap
	4）实例讲解
	a:实验开始前请先确认好你的swap情况
   	  free -m    //内存和交换分区的使用情况   
	b:建新分区  
	  ID指定为82   //新建交换分区的形式
	  如果是用文件的话，用如下格式建立swap虚拟文件
	  dd  if=/dev/zero  of=/tmp/swap bs=10M  count=100
	c:格式为swap
	  设备 mkswap  /dev/sdc1
	  文件 mkswap  /tmp/swap
	d:再次确认free
	e: swapon  /dev/sdc1    
         swapon  /tmp/swap
	f:再次确认free
