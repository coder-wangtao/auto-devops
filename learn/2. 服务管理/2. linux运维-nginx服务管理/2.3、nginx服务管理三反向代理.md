 1、在56.121上创建基于端口8080、8081的虚拟主机 //如下操作在56.121上进行

\#vim  /etc/httpd/conf/httpd.conf  

在Listen 80后们添加如下行

Listen 8080

Listen 8081

在文件末尾添加两个虚拟主机

<VirtualHost  *:8080>

  ServerName apache0.example.com

  DocumentRoot /var/www/html/apache0.example.com

  Errorlog  logs/apache0.example.com_error.log

  Customlog  logs/apache0.example.com_access.log  combined

</VirtualHost>

 

<VirtualHost  *:8081>

  ServerName apache1.example.com

  DocumentRoot /var/www/html/apache1.example.com

  Errorlog  logs/apache1.example.com_error.log

  Customlog  logs/apache1.example.com_access.log  combined

</VirtualHost>

 

\#mkdir  /var/www/html/{apache0.example.com,apache1.example.com}

\# echo  "192.168.56.121 apache 8080"  >/var/www/html/apache0.example.com/index.html

\#echo  "192.168.56.121 apache 8081"  >/var/www/html/apache1.example.com/index.html

\#service  httpd  start  

通过56.122进行验证,确保访问到对应内容

\#curl  192.168.56.121:8080

\#curl  192.168.56.121:8081

2、在56.122上配置nginx的反向代理

\#vim  /usr/local/nginx/conf/conf.d/nginx2.example.com.conf

![img](file:////private/var/folders/kg/qf7zkd8d53777cmxsn10mv0h0000gn/T/com.kingsoft.wpsoffice.mac/wps-hellen/ksohtml//wps7.jpg) 

从截图中可以看到设置了

1） upstream apache,里头包含了两个节点服务器56.121:8080 56.121:8081

2） 两个节点都设置了weight=5,权重一样基本是轮询的方式（负载平衡请参考“nginx的反向代理之负载平衡”）

3） proxy_set_header Host $host这里的Host变量是日志中的***\*$http_host\**** ,$host就是nginx代理机 

4） proxy_set_header X-Real-IP $remote_addr;将$remote_addr的值放进变量X-Real-IP中，此变量名可变，$remote_addr的值为客户端的ip.

5） proxy_set_header  X-Forwarded-For  $proxy_add_x_forwarded_for;都是显示出真实的客户端ip

6） proxy_set_header X-NginX-Proxy true;设置变量X-Nginx-Proxy为true

7） 后面的proxy_pass指向前面定义的upstream,在这里也可以直接指向一个域名地址。

2、 在56.122上进行反向代理设置

\#vim  /usr/local/nginx/conf/conf.d/nginx2.example.com.conf  

![img](file:////private/var/folders/kg/qf7zkd8d53777cmxsn10mv0h0000gn/T/com.kingsoft.wpsoffice.mac/wps-hellen/ksohtml//wps10.jpg) 

从截图中我们可以看到

1）proxy_pass  http://apache  proxy_pass http://dev/  proxy_pass http://test/

新增的proxy尾部多了个”/” 

没“/”：访问代理服务器地址nginx2.example.com/diy 转到后端节点就是http://node1/diy 

有“/”：访问代理服务器地址nginx2.example.com/dev 转到后端节点就是http://node1/

如果你不写“/”，也可以使用rewrite的方式来实现相同的效果

可以将proxy_pass http://dev/  改写成如下两行

rewrite ^/user/(.*)$ /$1 break;

proxy_pass http://dev;

2）location的配置规则，截图中用到了两种location  / 和location  ^~

= 开头表示精确匹配

^~ 开头表示uri以某个常规字符串开头，理解为匹配 url路径即可

~ 开头表示区分大小写的正则匹配

~*  开头表示不区分大小写的正则匹配

!~和!~*分别为区分大小写不匹配及不区分大小写不匹配 的正则

/ 通用匹配，任何请求都会匹配到

多个location配置的情况下匹配顺序为：

首先匹配 =，其次匹配^~, 其次是按文件中顺序的正则匹配，最后是交给 / 通用匹配。当有匹配成功时候，停止匹配，按当前匹配规则处理请求。
